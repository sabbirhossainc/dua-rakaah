# Proposal

## Why

Every category link in the sidebar (`/duas/<slug>?cat=N`) returns a 404, and the only content page (`/duas`)
renders all 190 rows as cards that show just a name, `top_en` and a reference. The Arabic text,
transliteration and translation never appear, and there's no way to read Bangla. This is phase 1 of
`plan.md`, and phases 2 to 4 (offline, bookmarks, audio) all build on these pages.

## What Changes

- **Category pages** at `/duas/<slug>?cat=N`, the URL shape the sidebar already links to. `cat` decides which
  category is shown. The slug is cosmetic: a wrong slug redirects to the canonical one, and a missing or unknown
  `cat` is handled explicitly. Duas are grouped under their subcategory headings, which replace the hard-coded
  "Section: Sections".
- **Full dua cards:** the title, the intro text (`top_*`), the Arabic text, transliteration, translation, the closing
  text (`bottom_*`) and the reference. A dua stored across several rows (8 duas use 22 rows) is shown as **one card
  with several parts**, so the app shows 176 duas, not 190 cards.
- **`/duas` becomes a category grid** (10 cards with icon, name and counts) instead of prerendering every dua.
- **Bangla through the URL:** `/bn/duas` and `/bn/duas/<slug>?cat=N` show the `_bn` columns and Bangla labels.
  The English URLs stay unprefixed. The language buttons in the Settings panel switch between the two.
- **Counts** in the sidebar and the grid come from the data, because the stored `no_of_dua` counts rows and is
  off by one for category 5.
- **Real 404 and 308 statuses:** the `loading.js` skeletons in `app/` and `app/duas/` are removed, because a streamed
  fallback would force status 200 (design D12).
- **Cleanups:** `LeftBar.js` export name, duplicate DOM IDs (`sec_1`, `cat_1`, and the icon IDs repeated in every `DuaIcons`), Tailwind classes that no theme
  defines, `<html className="p-10">`, the "Generated by Sabbir" description, and the favicon hot-linked from
  duaruqyah.com. The dead `http://` `<audio>` elements are removed until phase 4.
- **Content DB compacted** with `VACUUM` (6.7 MB to about 600 KB), after a check that no row changes.
- **Deployment:** the category pages render per request (because of `?cat=N`), so `data/dua_main.sqlite` is added
  to the server trace.
- **README rewritten** for the single-app layout.

Not in this change: search (plan item 1.7), the sidebar search input, `DuaIcons` behavior, the other Settings
panels, audio, and translating the global chrome (LeftBar, Topbar).

## Capabilities

### New Capabilities

- `dua-categories`: the category grid at `/duas`, the category list in the sidebar, and the category page URL
  (`?cat=N`, slug canonicalization, not-found handling) with duas grouped by subcategory.
- `dua-display`: what a dua card shows, how multi-part duas render, and the stable anchors for subcategories and duas.
- `content-localization`: English and Bangla content selected by URL prefix, Bangla UI labels, and the language switch.
- `content-database`: the shipped content DB stays identical in content when compacted, and is available to every
  page that reads it at request time.
- `site-shell`: site-wide metadata, favicon and the outer page frame.

### Modified Capabilities

None. There are no existing specs.

## Impact

- **Routes:** new `app/duas/[slug]/page.js`, `app/bn/duas/page.js`, `app/bn/duas/[slug]/page.js`, and
  `app/bn/duas/layout.js`. `app/duas/page.js` is rewritten.
- **Components:** `Category.js` (language-aware links, computed counts, unique IDs), `LeftBar.js` (export name),
  `RightBar.js` (working language toggle), and new card and section components.
- **Data access:** `lib/db.js` keeps parts in stored order. New pure helpers for grouping, slugs and language fields,
  with unit tests run by `node --test`.
- **Config:** `next.config.mjs` gets `outputFileTracingIncludes`. `package.json` gets `test` and `db:vacuum` scripts.
- **Data:** `data/dua_main.sqlite` is rewritten by `VACUUM`. Its content and `dua.id` values don't change.
- **Rendering model:** category pages are dynamic, not prerendered. This departs from the "SSG by default"
  decision in `plan.md` and affects phase 2. See `design.md`.
- No new runtime dependencies.
